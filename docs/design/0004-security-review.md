## 暂时没修（记录在案）

- **C3 写入不是一个事务**：录药方/采购时，新药材和新店铺先建好，后面的写入如果失败，它们会留下来。影响很小（多一个药材名或店名），以后可以把每个创建流程做成一个数据库函数。
- **识别失败后没用上的照片不会自动清理**：照片在私有 bucket 里，只有本家能看到，只是占空间。以后可以加一个定时任务清理没有关联药方的照片。
- **一家新建的药材名会出现在所有人的自动补全里**：药材目录是全局共享的。名字本身敏感度很低，但更严格的做法是：新建的药材先只对本家可见，审核后再进公共目录。
- **Storage 的 RLS** 在本地 Supabase-lite 上没有执行（本地存储是简化版），上线后需要手动验证。

## 结论

审查发现的两个高危问题（S1、C1）是在「家人共享」这条路径上：功能测试测的是「家人能看到共享数据」，没有测「不该看到的人看不到」和「一个人有两个药柜」。这类「对方不同意 / 身份重叠」的情况，以后加新的共享功能（MVP3 的医生、患者角色）时要先写测试。
