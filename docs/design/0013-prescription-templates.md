# 0013 · 基于已有药方开新处方：预设药方 + 复用（IDEA-3）

- 状态：已实现
- 日期：2026-11-08
- 作者：Hao、Claude
- 需求：`docs/ideas.md` IDEA-3

## 1. 目标

医生开方时不用每次一味一味选：可以从一张已有的药方开始（药材组合和克数导入表单当初稿），再按当前病人增删、改克数。

**2026-11-08 Hao 定的**：

- **先只给医生（诊所）账号**；病人账号以后需要再加
- 最常用的应该是**预设药方**（处方越开越多，搜索会很杂）。前期预设少，医生复用了一张**不是预设**的处方时，保存时提醒「要不要存成预设药方」
- **预设药方可以编辑**，编辑不影响以前从它开出的处方
- 开出去的是**独立的新处方**，以后改它不影响原来的
- 只能看到有权限看的处方，**不暴露其他病人的个人信息**

## 2. 数据模型

```sql
prescription_templates (
  id, workspace_id, name,              -- 同一个诊所里名字不重复，1–40 字
  dose_count, instructions, notes,     -- 剂数、煎服法、医嘱（可空）
  use_count, last_used_at,             -- 用了几次、上次什么时候（列表排序用）
  created_by, created_at, updated_at,
  unique (id, workspace_id)
)
prescription_template_items (
  template_id → prescription_templates on delete cascade,
  herb_id, grams_per_dose, special_prep, note, sort_order,
  primary key (template_id, herb_id)
)
prescriptions
  + source_template_id      -- 从哪个预设开的（可空）
  + source_prescription_id  -- 从哪张处方开的（可空）
```

- RLS 和处方一样按药柜（`is_member`）；明细跟着预设走
- **只有诊所能建预设**（触发器，和病人档案一样）
- 来源用复合外键 `(source_*_id, workspace_id)`，保证来源和新处方在同一个药柜；`on delete set null (source_*_id)`：删了预设或原处方，新处方的来源变成空，处方本身不受影响
- 给 `prescriptions` 加 `unique (id, workspace_id)`（复合外键要用）
- 只加表、加可以为空的列，旧代码不受影响

**来源只是记录**：新处方的药材是复制出来的，和来源没有联动。开方期间来源被删了（比如另一个标签页删了预设），保存时就当没照着开，来源记成空，不报错。

**写预设用数据库函数**（`security invoker`，权限照常走 RLS）：`create_prescription_template`（新建 + 明细）、`use_prescription_template`（用过次数原子加一；「同时更新预设」时一起覆盖剂数、煎服法、医嘱和明细）。一个函数是一个事务：明细不会只换一半；同时保存时按预设排队（`for update`）。

## 3. 页面

### 3.1 开方页：「从已有药方开始」

- 按钮打开选择面板（和 A–Z 选药一样用原生 `<dialog>`，挂在表单外面），三个筛选：
  - **预设药方**（默认）：名字 + 药材组成 + 用了几次，按最近用过的排
  - **当前病人的**：先选了病人才有；显示日期 + 药材组成
  - **全部**：这个诊所**最近 200 张**处方（面板上写明），**只显示日期和药材组成，不显示病人的名字、电话**。服务器查处方时就不取标题、病人、医嘱，浏览器拿到的数据里也没有
  - 「当前病人的」不受 200 张的限制：URL 带了病人时页面一起加载这个病人的全部处方；开方时才选 / 换病人，点「当前病人的」时按需加载；「照这张再开一张」的那张也单独加载
- 搜索：预设名字、药材名（「黄芪」找出含黄芪的）
- 选一张 → 药材、克数、脚注、备注导入表单，剂数和煎服法也带过来；表单里已经有药时先确认「替换现在的药材？」
- 表单上方显示「照着：预设『四君子汤加减』」或「照着：2026-10-15 的处方」，可以清掉

### 3.2 保存时

- 照着**处方**开的（不是预设）→ 保存按钮上方提醒：「这张是照着以前的处方开的，要存成预设药方吗？」+ 勾选框 + 名字。默认不勾；名字**默认是空的**（诊所处方的标题是「病人 + 日期」，不能当预设名，也不想把病人名字带进预设）
- 照着**预设**开的 → 勾选框「同时更新预设『…』」（默认不勾）：勾上就用这次的药材、克数、剂数、煎服法覆盖预设（**这就是编辑预设的方式**），以前开出的处方不受影响
- 什么都没照着 → 也可以勾「存成预设药方」
- 预设的 `use_count` 加一、`last_used_at` 更新
- 预设没存成 / 没更新成功时，处方照样保存，详情页分别提示（`tplerr=create` / `tplerr=update`），告诉医生怎么补救

### 3.3 预设药方管理 `/clinic/templates`

- 开方页的选择面板里有入口「管理预设药方」（**新标签页打开**，正在开的方子不会丢；不加到导航，导航的项目已经定了）
- 列表：名字、药材组成、用了几次、上次用；可以**改名**、**删除**（确认）、**用它开方**
- 改药材：用它开方，保存时勾「同时更新预设」

### 3.4 处方详情页（诊所的）

- 「照这张再开一张」→ 开方页，病人选好、药材导入（来源记成这张处方）
- 「存成预设药方」→ 起个名字，直接存

- 单元（`rx-reuse.ts`）：药材组成的摘要、搜索过滤、什么时候提醒存预设

  5. 按药材名搜
  6. 管理页改名、删除；家庭账号打不开
