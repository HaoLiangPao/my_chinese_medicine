# 0003 · MVP2：比价与每副药成本

- 状态：已实现（`mvp1-foundation` 分支）
- 日期：2026-10-27
- 作者：Hao、Claude

## 1. 目标

1. 同一味药，在哪家店买最便宜？各家差多少？
2. 一张方子，自己买药配，每副大概多少钱？和在诊所买比呢？
3. 家里药柜里的药值多少钱？

## 2. 规则

| 规则 | 理由 |
|---|---|
| 「某店现价」= 这家店最近一次采购的每克单价；同一天买了多次，取最后录入的 | 价格会变，看最新的 |
| **价格 0 的采购视为赠品，不参与比价** | 否则送了一次就永远是「最便宜」 |
| 赠品**计入**平均成本 | 平均成本反映的是实际花了多少钱 |
| 没有价格的药，在成本里单独列出，不计入合计 | 不能假装它是 0 元 |
| 有药没价格时，**不和诊所比较** | 少算了钱再比，会误导「自己买更便宜」 |
| 药柜价值 = Σ 正库存 × 加权平均成本；负库存按 0 | 负库存是账没记全，不是负资产 |
| 店铺有类型：诊所 / 药行 / 网店。类型只在第一次录入这家店时设置 | 「李医生诊所」也可以当作一家店来比价 |

## 3. 数据库

`supabase/migrations/20261027000005_pricing.sql`：

| 对象 | 内容 |
|---|---|
| `v_store_latest_prices` | 每味药 × 每家店：现价、最近日期、买过几次 |
| `v_herb_price_summary` | 每味药：几家店有价、最便宜的店、最低/最高价、价差 %、加权平均成本 |
| `prescription_cost(药方, 策略, 店)` | 每味药的每副成本。策略：`cheapest` 各店最低价 / `average` 平均成本 / `store` 指定一家店 |
| `prescription_cost_by_store(药方)` | 如果全部在一家店买：每副多少钱、缺几味；缺得少的排前面 |
| `v_inventory_value` | 每味药的库存价值 |

全部遵循调用者的 RLS（视图 `security_invoker`，函数 `security invoker`）。

## 4. 界面

- **比价**（新页面 `/prices`）：药材 × 店铺的价格表（每 100 g），最便宜的高亮，按价差从大到小排；可以只看药方里用过的药；底部统计每家店有几味药最便宜；顶部显示药柜价值。
- **药方详情 → 成本**：三种算法切换（各店最低价 / 我买入的平均成本 / 只在某家店），每味药的单价、来源、每副成本；合计每副和总价；填写「诊所实付」后显示每副差多少；「如果全部在一家店买」列表。
- **采购**：新增「店铺类型」。
- **药柜**：顶部显示总价值。

## 5. 测试

- **单元测试** `src/lib/pricing.test.ts`：策略参数解析、成本汇总（完整/不完整/没填诊所价/自己买更贵/赠品/空方/0 副）、每 100 g 换算、选最便宜的店（忽略赠品、同价按店名）。
- **SQL 测试** `supabase/tests/pricing_test.sql`：手算好的数字逐一断言。包括同一天两次采购取后录入的、赠品不参与比价但计入成本、只有赠品的药、三种成本策略、各店对比排序、负库存价值、RLS。
- **E2E** `e2e/mvp2.spec.ts`：在 scenario 的 5 家店数据上，测试独立算出每个价格、价差、「最便宜次数」、四君子汤三种策略的成本、各店对比顺序、诊所比较、药柜价值，再和页面逐一核对。最后录入一家诊所，价格更低时它成为最便宜的。

## 6. 以后可以做

- 炮制品没有价格时，参考原药材的价格（标注「参考」）
- 价格走势（同一家店的历史价格）
- 「最省钱的买法」：一张方子拆开到不同店买，算出最省的组合，加上运费或交通成本
- 采购小票拍照识别（复用药方识别那一套）
