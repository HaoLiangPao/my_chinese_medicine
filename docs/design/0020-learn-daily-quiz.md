## 1. 为什么

2026-11-14 Hao：在学堂里做一个「每日一题」，关于中医的小知识，慢慢积累成题库、可以复习；题目按类型分（五行、针灸、阴阳、某一本书……），用来吸引用户使用学堂。不确定的先做决定、记下来，他回来再斟酌（§9）。

## 2. 边界：只考知识

和全站一样，AI 只做转录和科普（CLAUDE.md）。题目只考知识：

- 可以：理论（阴阳、五行、脏腑、气血津液）、典籍的成书和作者、名句出处、药材的功效**分类**和四气五味、炮制常识、方剂的**组成和出处**、经络和穴位的名称、归经、定位、四诊的概念
- 不出：用量、剂量题；「某病 / 某症该吃什么药、用什么方」这类治疗题；「方剂主治什么」也不出
- 有争议、教材说法不一的题不出（比如方剂的最早出处有两种说法的，只考组成）

`quiz-bank.test.ts` 用两个正则挡：数字 + 用量单位（g、克、钱、两、丸……；「犊鼻下 3 寸」「365 种」不算），和「用量、剂量、服用、主治、适应证、吃什么药、患者……」这些说法。测试里有反向用例（这些例子必须被挡住）。

## 3. 题库

### 3.1 数据

`supabase/data/quiz-questions.json` 是唯一来源，用 `scripts/gen-quiz-questions.mjs` 生成 migration（参照 `gen-herb-monographs.mjs`）。

| 字段 | 说明 |
|---|---|
| `id` | `<主主题>-<三位数>`，比如 `wuxing-003`。**不能改**（作答记录指向它） |
| `topics` | 主题，1–4 个，第一个是主主题 |
| `kind` | `single`（单选，4 个选项）或 `judge`（判断，选项固定是「对 / 错」，题干以「判断：」开头） |
| `stem`、`options`、`answer` | 题干、选项、正确选项的下标（从 0 开始） |
| `explanation` | 解析，一两句（≤ 120 字），不大段引原文 |
| `source` | 出处：经典篇名（《黄帝内经·素问·阴阳应象大论》）或「某某教材通行说法」 |
| `difficulty` | 1–3 |
| `status` | `draft`（AI 整理）/ `reviewed`（医生审核过，要有 `reviewed_by`、`reviewed_at`）/ `retired`（发现有错，下架） |

数据库表 `quiz_questions` 的约束和这些一致（答案在选项里、主题在列表里、判断题的选项、审核过的要有审核人……）。选项不重复、单选是 4 个、解析长度、正确答案的位置要分散（每个位置 15%–35%）这些由单元测试检查。

### 3.2 生成的 migration

整份 JSON 放进一个 `$quiz$…$quiz$` 字面量，`jsonb_to_recordset` 展开后按 id upsert：新题插入，内容变了的更新（`updated_at` 跟着变），没变的不动。可以重复执行（本地验证过：执行两遍，题数不变，被改坏的那题恢复，其他题没被碰）。

- 这一版的 migration（000027）= 手写的建表 + 生成的数据块（`-- >>> 题库` 到 `-- <<< 题库` 之间）。还没上线时改了 JSON 用 `--update` 重新生成数据块
- 以后加题、改题：改 JSON，`node scripts/gen-quiz-questions.mjs supabase/migrations/<新时间戳>_quiz_questions_<名字>.sql` 生成一个只有数据块的新 migration
- 题目不删，要下架改成 `retired`
- `quiz-bank.test.ts` 检查**最新**一个带题库的 migration 里的字面量和 JSON 完全一致：改了 JSON 忘了生成 migration，单元测试就失败

## 4. 每日一题

- 位置：学堂首页 `/learn` 顶部的卡片
- **同一天所有人同一题**，按多伦多的日期：题目按 id 的 FNV-1a 哈希排成一个固定顺序（打乱主题），从 1970-01-01 起第 n 天出第 `n mod 题数` 道。题库不变时，同一道题两次出现正好隔「题数」天（现在是 123 天）。纯函数在 `web/src/lib/quiz.ts`（`dailyQuestionId`），单元测试：同一天结果一样、连续 N 天每题正好一次、跨 1970 年取模不出负数、加题以后原来的题先后不变
- **不登录也能做**：答完显示对错、正确答案、解析和出处；提示「登录后可以记录和复习」。不登录不写数据库，刷新后又是没答的样子
- 登录用户：记一条 `mode = 'daily'` 的作答，打卡。今天已经答过的，页面显示他答的那题和结果
- **答案不提前发给浏览器**：页面上只有题干和选项，点了选项由 server action（`answerQuestion`）判分、返回解析。对错在数据库里由触发器按题库的答案再算一遍写进记录，浏览器改不了
- 每日一题的作答要求题目就是今天那题（服务器上再算一遍），日期变了提示刷新

已知的小问题：题库加题或下架时，顺序整体错开，**当天**的题可能换一道。已经答过的人不受影响（页面显示他答过的那题）；还没答的人看到新的那题。加题的 migration 在晚上合并，影响很小。

## 5. 记录和复习（登录用户）

### 5.1 数据

`quiz_attempts`：每次作答一行（`user_id`、`question_id`、`chosen`、`correct`、`mode`：daily / practice / review、`daily_day`、`answered_at`）。

和库存一样是流水账：复习进度、打卡天数、做过的题都从这些记录现算（`web/src/lib/quiz.ts`），**不存「复习进度」字段**，算法以后改了也不用迁移数据。

权限（`supabase/tests/quiz_test.sql`）：

- 题库：anon 和登录用户都只能读；谁都不能加、改、删
- 作答：只能读、插自己的；没有 update、delete。插入只能写 `question_id`、`chosen`、`mode`、`daily_day` 四列：`user_id`、`answered_at` 用默认值，`correct` 由触发器算
- anon 不能读写作答
- 每日一题每人每天一条（唯一索引），`daily_day` 只能是今天（多伦多），不能补以前的卡、也不能提前打卡
- 下架的题不能再答（以前的记录还在）
- 防刷：每人 24 小时最多 500 次作答（App 正常用碰不到）
- 删账号时作答一起删

### 5.2 间隔复习

只有**答错过**的题进复习（第一次就答对的算会了）。按时间顺序看每一次作答（日期按多伦多）：

- 答错：1 天后复习，进度清零（任何时候答错都算，包括没到复习日、已经掌握了的）
- 到了复习日（或者过了）答对：进度 +1，下一次间隔依次是 3、7、14 天（从答的那天算）；14 天那次也答对 → **掌握了**
- 没到复习日答对（比如练一练又抽到）：不改变复习日

复习页 `/learn/quiz/review`：今天到期的题，到期早的先出，一组 5 题；没有到期的显示下一次复习的日子。

### 5.3 其他

- **练一练** `/learn/quiz/practice?topic=…`：按主题（或全部）抽 5 题，先抽没做过的。不登录也能练，只是不记录
- **我做过的题 / 错题本** `/learn/quiz/mine`：按主题筛；显示最近一次对错、正确答案、解析（点开）、复习状态（某月某日复习 / 今天复习 / 已掌握、错过几次）
- **连续打卡**：只算每日一题。今天答了从今天往前数，今天还没答从昨天往前数（今天还来得及）
- **主题进度**：每个主题做过几道 / 一共几道

## 6. 吸引人一点，但别太闹

- 答对：「答对了！」一个小的放大动效（CSS，0.6 秒），系统设置了减少动态效果的不播
- 打卡天数在每日一题卡片的右上角
- 题库首页：连续打卡、今天要复习、错题本、做过几道四个数；主题列表带进度条
- 没有积分、排行、徽章、声音

## 7. 内容可靠性

- 题目由 AI 按教材的通行说法整理，状态都是 `draft`
- 题目下方一行小字：「题目由 AI 整理，尚未经医生审核；发现错误请点右下角「反馈问题」」。没登录的人没有反馈按钮（0014：登录后才有），所以没登录时写成「请登录后点右下角「反馈问题」」
- 题库首页底部说明：题目只考知识、不涉及用药和剂量建议
- 发现错题：改 JSON（改内容，或者 `status: retired`）→ 生成新 migration
