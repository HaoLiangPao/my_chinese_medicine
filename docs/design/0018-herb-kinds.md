# 0018 · 药材的来源和入药部位（带图标）

- 状态：已实现（migration `20261114000026_herb_kinds.sql`），分类结果和 §8 的决定待 Hao、李医生看
- 日期：2026-11-14
- 作者：Hao、Claude
- 相关：0017（药材目录，430 味原药材 + 77 个炮制品）、0010（药材资料）、0004 S2（共享目录只能由我们加）

## 1. 为什么

2026-11-14 Hao：「不同的药材有没有什么特殊的组合，分类，比如说矿物类，植物类，动物类，野生类等？可不可以给每一个类做一个 icon，像你给不同的 tab 做的 icon 一样」。他说有不确定的先做决定、记下来，回来再斟酌（§8）。

目录现在只有「功效分类」（`category`，补气药、清热药……）。药柜里实际摆的时候、认药的时候，常用的是另外两种分法：这味药是植物、动物还是矿物；是根、果实还是花。

## 2. 三个维度

| 维度 | 列 | 取值 | 谁有 |
|---|---|---|---|
| 功效分类（已有，不动） | `category` | 解表药、清热药……（24 类，0017） | 目录里的每味药 |
| 来源 | `origin_kind` | `plant` 植物、`fungus` 菌藻、`animal` 动物、`mineral` 矿物、`manufactured` 加工品 | 目录里的每味药 |
| 入药部位 | `medicinal_part` | `root` 根及根茎、`fruit_seed` 果实种子、`whole` 全草、`leaf` 叶、`flower` 花、`bark` 皮、`stem` 茎木、`resin_other` 树脂及其他 | 只有植物 |

分法照《中国药典》2020 年版一部各药「来源」项写的药用部位，和《中药学》《生药学》教材的通行分法：

- **菌藻**：真菌和藻类（茯苓、猪苓、雷丸、灵芝、马勃、冬虫夏草、海藻、昆布）。
- **加工品**：人工制成、已经不是某种药材的某个部位的：发酵（神曲、淡豆豉）、熬胶（阿胶、龟甲胶、鹿角胶）、加工提取（青黛、儿茶）、合成（冰片）。天然的渗出物、汁液不算加工品，算植物 · 树脂及其他（乳香、没药、血竭、芦荟）。
- **根及根茎**包括块根、块茎、鳞茎（半夏、贝母、百合、薤白）；**果实种子**包括果皮（陈皮、青皮、瓜蒌皮）和假种皮（龙眼肉）；**皮**只指树皮、根皮（黄柏、牡丹皮、杜仲）；**花**包括花蕾、花序、花粉、柱头、雄蕊（辛夷、蒲黄、西红花、莲须）；**茎木**包括藤茎、嫩枝、心材、茎髓、棘刺（鸡血藤、桂枝、檀香、通草、皂角刺）；**树脂及其他**是树脂、汁液、孢子、虫瘿、分泌物（乳香、芦荟、海金沙、五倍子、天竺黄）。
- **化石**（龙骨、龙齿、琥珀）按《中药学》算矿物。

数据库存英文代码（和 `herb_monographs.toxicity` 一样），页面上显示中文；代码和中文的对照、显示顺序在 `web/src/lib/herb-kinds.ts`。

## 3. 数据

### 3.1 列和约束

```sql
alter table public.herbs
  add column origin_kind    text check (origin_kind in ('plant', 'fungus', 'animal', 'mineral', 'manufactured')),
  add column medicinal_part text check (medicinal_part in ('root', 'fruit_seed', 'whole', 'leaf', 'flower', 'bark', 'stem', 'resin_other'));
-- 植物一定有部位，别的（包括还没分类的）一定没有
alter table public.herbs add constraint herbs_medicinal_part_plant_only
  check (case when origin_kind = 'plant' then medicinal_part is not null else medicinal_part is null end);
```

- 两列都可以为空：用户自己加的药（App 只允许写 `name_zh`）是空的，页面上显示「未分类」。
- 用 text + check，不用 enum：以后加一类只要换 check（和 `toxicity`、`special_prep` 一样）。
- **谁都不能改**：沿用目录只读的规则（0004 S2、`20261027000007` 只把 `insert (name_zh)` 给了 `authenticated`）。新列没有授权给 `anon` / `authenticated`，所以客户端既不能在新增时写、也不能改；SQL 测试 `herb_kinds_test` 覆盖。

### 3.2 数据从哪来、怎么上线

- 正式来源：`supabase/data/herb-kinds.json`，按「来源 → 部位 → 药名」列 430 味原药材；`processed_overrides` 写和原药材不一样的炮制品；`uncertain` 写每味拿不准的理由（§7）。
- `scripts/gen-herb-kinds.mjs` 读 JSON 和 `seed.sql`，生成 migration：加列 → 加约束 → 按药名填（**只填还是空的**，可以重复执行）→ 检查名单里在库里的药都填上了。做法和 `gen-herb-monographs.mjs` 一样：生成以后不手改；以后改分类就改 JSON，生成一个新的 migration（那时要把「只填空的」换成明确的 update，写进那个 migration）。
- 以后目录加新药（改 seed.sql），单元测试会要求 JSON 里也有它。
- 以后改分类时：改 JSON → 生成新的 migration（把生成脚本的「只填空的」换成按名字明确 update 改动的那几味）→ `herb-kinds.test.ts` 里「生成的 migration」那一段改成检查新的 migration；`20261114000026` 已经上线，不再和 JSON 比。

### 3.3 炮制品：存，跟原药材

炮制品**也存自己的值**，由生成脚本按 `seed.sql` 里的原药材算（`processed_overrides` 里的例外），而不是只存原药材、读的时候再去找原药材。理由：

1. 按名字填，能覆盖用户早先自己建的同名药：升级测试里用户自己建过「红参」（没有挂到人参下，0017 §4），只存原药材的话它永远是「未分类」。
2. 数据库里直接按来源统计、分组（以后管理员看板、学堂可能用到），不用每次都连原药材。
3. 有例外：胆南星是制天南星加胆汁发酵制成的，算加工品，不跟天南星（植物 · 根及根茎）。

读的时候还留一个兜底（`resolveHerbKind`）：自己是空的、原药材有值，就用原药材的。正常不会用到（目录里的炮制品都存了），防的是以后哪个 migration 加了炮制品却忘了填。

### 3.4 已有数据（升级测试 `supabase/tests/upgrade/20261114000026_herb_kinds.sql`）

| 情况 | 做法 |
|---|---|
| 目录里的药（包括 #34 新加的） | 按名字填上 |
| 用户自己加的、名字和目录里的药一样（延胡索、红参） | 按名字填上：就是那味药（0017 已经把新别名、新炮制品挂在它上面） |
| 用户自己加的、目录里没有的名字（云苓、茯神……） | 不填，「未分类」 |
| 已经有值的 | 不改（重复执行什么都不变） |

只加可以为空的列、填数据，正在线上跑的旧代码不读这两列，不受影响。

## 5. 页面

- **药材页 `/herbs` 的目录**：上面两个切换「按功效」「按来源」（地址栏 `?by=origin`，默认按功效，和 #34 一样）。
  - 按功效：分组和以前一样；每味药的小标签前加来源的小图标（14px），鼠标悬停显示「植物 · 根及根茎」。
  - 按来源：植物按部位拆开，一共 13 组：根及根茎、果实种子、全草、叶、花、皮、茎木、树脂及其他（标题写「植物 · 根及根茎」）、菌藻、动物、矿物、加工品、未分类；组标题前是这一组的图标。组内的小标签不再放图标（每个都一样，只是多余）。
- **药材详情页**：名字下面的小标签行最前面加「〔图标〕植物 · 根及根茎」，有资料的药后面接着性味、归经、毒性；没有资料的药也显示这一个。用户自己加的药显示「未分类」。
- **选药（家庭 A–Z RX-5、诊所开方 CLN-3）不加**：一行一味药，再加图标会挤，而且选药时找的是名字。

## 6. 不做的

- **野生 / 栽培不做成药材的分类**：同一味黄芪有野生的也有栽培的，这是某一批货的属性，不是这味药的属性。以后可以给批次（`purchase_items`，0010 §9 已经有产地、批号）加「野生 / 栽培」。
- 动物药的部位（角、甲、贝壳、全体、分泌物……）、矿物的类别（钙、铁、汞……）这一版不分。
- 不做按来源筛选、搜索；只是分组切换。

## 8. 待 Hao 斟酌的决定

每条：做了什么、为什么、还可以怎么做。

1. **两个新维度：来源（5 类）+ 入药部位（8 类，只给植物），功效分类不动。**
   为什么：这是药典和教材的通行分法，李医生熟悉；两个维度分开，比一个混合的列表（「矿物、动物、根、花……」）清楚。
   备选：只做来源一个维度（更简单，但植物占八成以上，按来源分组时「植物」一组 400 多味，没什么用）。
2. **菌藻单独一类，不归植物；菌藻不填部位。**
   为什么：现代分类里真菌、藻类不是植物，《生药学》也单列（藻、菌、地衣类）；茯苓的「菌核」、昆布的「叶状体」放进根、叶都不对。
   备选：并进植物，部位填「树脂及其他」。
3. **「加工品」的边界：发酵、熬胶、加工提取、合成的算；天然渗出物、简单炮制的不算。**
   为什么：用户眼里阿胶、神曲已经不是「某种动物 / 植物的某个部位」。但「炮制」本身（炒、炙、煅）不改变来源，否则 77 个炮制品全成了加工品。
   备选：加工品只留神曲、阿胶这类，青黛、儿茶、淡豆豉归回原植物（见 §7）。
4. **炮制品存自己的值、默认跟原药材，胆南星例外算加工品**（§3.3）。
   备选：只给原药材存，炮制品读的时候查原药材（少一份数据，但用户早先建的同名药会是「未分类」，统计也要连表）。
5. **化石（龙骨、龙齿、琥珀）算矿物。**
   为什么：《中药学》这么归；药柜里它们和矿物药放在一起、都要先煎。
   备选：龙骨、龙齿算动物（古代哺乳动物的骨骼和牙齿），琥珀算植物（树脂化石）。
6. **野生 / 栽培不做成药材的分类，以后可以给批次加**（§6）。
   为什么：同一味药两种都有，是货的属性。放在批次上，以后批次标签上也能印。
   备选：现在就给批次加一个「野生 / 栽培 / 不知道」（要改进货表单和标签，单独一个 PR）。
7. **目录页按来源分组时，植物按部位拆成 8 组（一共 13 组）；组内标签不再放图标。**
   为什么：植物 425 味放一组太长；拆开以后每组 10–140 味，和功效分组差不多。
   备选：先按来源分 5 组、植物组里再按部位分小组（两层折叠，手机上点的次数多一次）。
8. **选药（家庭 A–Z、诊所开方）不加来源图标。**
   为什么：选药一行一味药，找的是名字；加图标会挤，也会分散注意。
   备选：在药名后面加一个很小的来源圆点（颜色区分），这一版没做。
9. **用户自己加的药显示「未分类」，App 里不能自己分。**
   为什么：目录全站共用、只读（0004 S2），一个用户随手选的分类会显示给所有人。
   备选：让用户给「自己加的药」选来源（只影响没有分类的药，但还是全站共用，需要审核流程）。
10. **数据库存英文代码，页面显示中文。**
    为什么：和 `toxicity` 一致；以后改中文叫法（比如「菌藻」改「真菌藻类」）不用动数据。
    备选：直接存中文（和 `category` 一致，查库时更直观）。
11. **分类由 AI 按药典整理，没有逐条对照原文**；§7 列的是拿不准的，其余的也建议李医生过目时一起看。
