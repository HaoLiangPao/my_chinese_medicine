## 2. 数据模型

```sql
bug_reports (
  id,
  reporter_id   → auth.users，默认 auth.uid()；账号删除后变空，报告留着
  workspace_id  → workspaces（可空：还没选账号类型的用户也能反馈）；药柜删除后变空
  page_path,              -- 脱敏后的路径，≤ 300 字
  description,            -- 用户写的，1–2000 字
  user_agent, viewport,   -- 浏览器 UA（≤ 300 字）、视口「宽x高」
  app_version,            -- 部署的 commit（服务器填，§4）
  recent_actions jsonb,   -- [{t, kind, label}]，最多 20 条
  recent_errors  jsonb,   -- [{t, message, stack}]，最多 5 条
  status,                 -- new（新）/ in_progress（处理中）/ fixed（已修）/ wontfix（不修），默认 new
  created_at
)
bug_report_usage (user_id, day, count)   -- 每人每天提交了几次（防刷）
```

**权限**

- RLS：登录用户只能**插入自己的**（`reporter_id = auth.uid()`，带药柜时必须是这个药柜的成员，`is_member`）、只能**读自己提交的**。同一个药柜的其他成员也读不到（描述里可能写了不想让家人 / 同事看到的内容）
- 提交人能写的列用**列级授权**限制：只有 `workspace_id、page_path、description、user_agent、viewport、app_version、recent_actions、recent_errors`。`status`、`reporter_id`、`created_at`、`id` 不能由提交人指定，只能用默认值
- 没有 update / delete 授权：**状态不能由提交人修改**，报告提交后也不能改、不能删。改状态现在由管理员在 SQL Editor 里做，以后由 IDEA-4 的后台做
- `anon` 没有任何权限
- 表上的 check 约束再限制一遍长度和条数（数据库是最后一道）

**防刷**：每人每天最多 20 条。写法和 `consume_parse_quota` 一样（`bug_report_usage` 计数、原子的 `insert … on conflict do update … where count < 上限`），但放在 `bug_reports` 的 **before insert 触发器**里，上限写在数据库里。原因：这张表允许登录用户直接插入，如果像 `consume_parse_quota(p_limit)` 那样由调用方传上限、由 App 调用，绕过 App 直接调 API 就没有上限了。超过时报错「今天的反馈次数已用完」，这一次不计数。「一天」按数据库的日期（UTC），和识别次数一样。

**兼容线上旧代码**：只加新表、新函数，旧代码不碰它们。

## 3. 页面

- 登录后的每个页面右下角有一个悬浮按钮「反馈问题」（家庭账号、诊所账号、还没选账号类型的都有；没登录时没有）。放在根布局里
- 手机上（< 640px）只显示图标，44×44 px；桌面上显示图标 + 文字。位置固定在右下角，离边 16px
- **不挡住页面底部的按钮**：页面内容（`main`）底部多留 96px 的空白，滚到底时最后一个按钮（比如开方页的「保存」）在悬浮按钮上方。现在没有固定在底部的导航（导航在顶部）；选药、选药方的弹出面板是模态的原生 `<dialog>`，会盖住悬浮按钮
- 打印时隐藏
- 点开是一个面板（原生 `<dialog>`，手机上从底部弹出）：
  - 描述（必填，最多 2000 字）。提示「不要写病人的姓名、电话」
  - 「会附带这些信息」的说明，可以展开看**这一次实际会带上的内容**（路径、操作记录、错误、浏览器）
  - 提交
- 描述为空（或只有空格）时提交按钮点不了；服务器也会拒绝
- **成功**：面板里显示「已收到，谢谢！」和报告编号的前 8 位，描述清空
- **失败**（断网、服务器出错、次数用完、登录过期）：面板里显示原因，**写的内容还在**，可以再点提交。草稿同时存在浏览器的 `sessionStorage` 里（按用户 id 区分，关掉标签页就没了，提交成功后清掉），页面被整个刷新（比如登录过期被带到登录页再回来）也还在

## 4. 自动收集和脱敏

| 内容 | 怎么来 | 脱敏和上限 |
|---|---|---|
| 当前路径 | `location.pathname + search` | **query 只留参数名、去掉值**（`?patient=…` → `?patient`）；去掉 `#` 后面的；路径里的 uuid 保留（是内部 id，定位问题要用），其他段照文字规则遮住；≤ 300 字 |
| 最近的操作 | 浏览器内存里的一个队列 | 最多 20 条；按钮上的字 ≤ 40 字，路径 ≤ 120 字。只有两种：**去了哪个页面**（脱敏后的路径）、**点了哪个按钮**（按钮上的字）或**链接**（只记目标路径「→ /路径」，不记链接上的字；和按钮一样 ≤ 40 字，完整的路径在紧跟着的「去了哪个页面」里） |
| 最近的前端错误 | `window` 的 `error`、`unhandledrejection` | 最多 5 条；message ≤ 300 字、stack ≤ 1000 字。message 和 stack 里不是「帧」的行按文字规则遮住；stack 的每一帧（`at …` 或以 `:行:列` 结尾的行）只遮邮箱，文件名里的哈希和行列号留着，不然线上压缩过的代码对不回源码 |
| 浏览器 | `navigator.userAgent`、视口宽高 | UA ≤ 300 字 |
| App 版本 | **服务器**填：`VERCEL_GIT_COMMIT_SHA`，没有时用 `VERCEL_DEPLOYMENT_ID` | — |
| 时间 | 数据库 `now()` | — |

**文字规则**（`redactText`）：邮箱 → `[邮箱]`；连续 6 位以上的数字（中间可以有空格、`-`、`.`、括号，开头可以有 `+` 或括号）→ `[数字]`，电话、身份证号、卡号都在里面；uuid 保留。

**绝不记的**：输入框、文本框、下拉框的内容（点击输入框不记录，也从不读 `value`）；键盘输入；页面上的其他文字。

**按钮上的字可能就是病人信息**（比如开方页搜病人的结果，每一行是一个按钮，上面是姓名和电话）。规则：

- 这类区域在外层加 `data-bug-private`，里面的按钮只记成「（已隐藏）」。现在加了的：开方页的病人搜索结果、「从已有药方开始」的列表（预设药方的名字是用户起的）、开方页的「＋ 新增「…」」按钮（上面是搜索框里打的字）、药柜卡片的标题（上面有用户填的罐子标签）
- 遮之前先把字符串切到上限的 4 倍再遮、再截到上限：遮的正则在很长的字符串上很慢，不能让一个巨长的字段把服务器卡住；留 4 倍是为了截断的地方不留半个电话
- **以后新加的按钮，上面如果会出现病人姓名、电话或者用户输入的内容，要包在 `data-bug-private` 里**（写进了 CLAUDE.md）
- 兜底：文字规则会遮住电话和邮箱（比如「退出登录 xxx@…」）；按钮上的字 ≤ 40 字；面板里可以展开看到这次会带上的全部内容
- 正则认不出中文姓名，所以这一条靠标记，不靠正则。这是已知的限制

**不信任浏览器**：脱敏和截断是纯函数（`web/src/lib/bug-report.ts`，有单元测试）。浏览器收集时做一遍，server action 收到后用同一套函数**再做一遍**（`normalizeBugReport`：类型不对的丢掉、条数和长度截到上限、文字再遮一遍），数据库的 check 约束是第三道。

**描述不脱敏**：是用户自己写的，原样保存（面板上提醒不要写病人信息）。只有发到 Slack 的那 100 字会按文字规则遮一遍（§6）。

**和 IDEA-5 原来的设想不一样的地方**

- 服务器端错误表（按请求 id 关联）没做。Vercel 的日志保存时间短这个问题还在，以后单独做
- 「最近的前端错误」只有没被处理的异常，不包括失败的网络请求

## 5. 为什么第一阶段不做页面截图

这个 App 的页面上到处是病人的姓名、电话、处方。截图要可靠地遮住这些信息，代价高：

- 在浏览器里把页面画成图片（html2canvas 一类）：要给每一处病人信息加标记、截图前替换成色块，**漏标一处就是泄露**，而且漏了没有测试能发现；库本身对一些 CSS 画得不准
- 浏览器的屏幕共享接口（`getDisplayMedia`）：准确，但每次都要用户点允许，而且拍到的是整个标签页，没办法遮
- 截图还要一个私有的 storage bucket、清理规则、管理后台里的查看权限

第一阶段用「路径 + 操作记录 + 错误」代替，大多数问题够定位了。

**以后怎么做**（建议）：

1. 先有 IDEA-6 的同意书（写明反馈会带截图）
2. 页面上所有显示病人信息的元素统一加标记（可以复用 `data-bug-private`），截图前换成色块；默认遮住所有输入框
3. 提交前让用户看到截图，可以选择不附
4. 截图存私有 bucket，路径以报告 id 开头，只有提交人和管理员能读；跟着报告一起删

## 6. Slack 通知（接口已写好，默认不发）

`web/src/lib/bug-notify.ts` 的 `notifyBugReport()`：

- 读环境变量 `SLACK_BUG_WEBHOOK_URL`。**没配置就直接返回，不发任何请求**
- 配置了：提交成功、响应发出去之后（`after()`，不拖慢用户）发一条消息，内容只有：**报告 id、页面路径、时间、描述的前 100 字**（按 §4 的文字规则遮过）。不带操作记录、错误、浏览器信息、提交人
- 发送失败（超时 5 秒、Slack 报错）只记日志，不影响提交；日志里不打印 webhook 地址
- 地址必须是 `https://`（本机地址 `localhost` / `127.0.0.1` 可以用 `http://`，E2E 用）

> IDEA-5 原来写的是「Slack 消息里不放描述原文」。2026-11-08 Hao 定的是放前 100 字，所以加了遮电话 / 邮箱这一步。描述里的中文姓名遮不掉：配置之前要知道这一点，频道只拉需要看的人。

**怎么配置**

1. Slack → 建一个 App（或用已有的）→ Incoming Webhooks → 打开 → Add New Webhook to Workspace → 选频道，复制 `https://hooks.slack.com/services/…`
2. Vercel → 项目 → Settings → Environment Variables → 加 `SLACK_BUG_WEBHOOK_URL`（只加 Production；这是密钥，不要提交到仓库）
3. 重新部署（环境变量在部署时生效）
4. 用测试账号提交一条反馈，频道里应该出现一条消息
5. 想关掉：删掉这个环境变量，重新部署

- E2E `bug-report.spec.ts`（@PLAT-3）：

  6. 手机 390px：按钮 ≥ 44px；录方、采购、开方页滚到底，「保存」按钮不被挡住、点得到；不横向溢出
